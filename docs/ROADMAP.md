# Lastclick Pigeon — 現状と将来展望

最終更新: 2026-10-29

## プロダクト定義

> **AI で書いた投稿を、そのまま各 SNS の投稿画面に届ける。**
> 整形・画像・タグまで入力して止まり、最後のクリックはあなたがする。

| 項目 | 定義 |
|---|---|
| ターゲット | **AI を使って投稿する人** |
| 入力 | **AI の出力そのもの**(Markdown / プレーンテキスト)。人が手で整形した前提にしない |
| 楽にする摩擦 | ① 媒体ごとの整形(note の見出し、X の文字数、IG のハッシュタグ)② 画像・動画の添付 ③ 投稿画面まで持っていく手間 |
| コア体験 | **1 本の AI 出力 → 複数媒体の下書き**。note 記事を作ったら、告知ツイートの投稿画面も同時に開く |
| やらないこと | AI による生成そのもの(ChatGPT / Claude に任せる)、公開ボタン、予約投稿、分析 |
| 媒体の優先順位 | AI 投稿者が実際に使っている順。**まず note**、次に X、その後 TikTok / Instagram |

媒体は手段で、主語は「AI で書く人」。ツールは賢くならず、運ぶだけに徹する(AI 側に front matter 付きで出力させる)。

## 思想

**The last click is yours.**

AI で生成した投稿を SNS に載せるまでの「コピペ・整形・画像登録・タグ付け」を機械に任せ、
**投稿・公開ボタンだけは人間が押す**。この線は機能ではなく設計の境界であり、今後も越えない。
全媒体に共通して適用する。

理由は3つある。

1. **規約・凍結リスク**: 完全自動投稿は各プラットフォームの規約で禁止または灰色。下書きまでなら影響が小さく、note は 2026-10 に公式 API でも「下書き保存まで・公開は画面から」という形を採用した
2. **品質**: AI 生成物を無確認で公開する運用は、アカウントを危うくする
3. **信頼**: 「公開ボタンを押さない」「認証情報を預からない」を名乗れることが、配布時の信頼の根拠になる

加えて、**一度に一投稿・連続投入なし**をツール側で固定する。note が 2026-02 に取り締まりを強化した対象は「機械的な大量投稿・外部サービスを利用した組織的な悪用」であり、大量投稿の道具に見えない設計を保つ。

### 長期(半年〜): 媒体を増やす

**全媒体で「下書きまで作り、投稿は本人のクリック」を貫く。公式 API は使わない。**
公式 API は X の従量課金、Instagram の Advanced Access(法人確認)、TikTok の監査制が壁になるが、
下書きまでなら API が不要で、費用と審査を丸ごと迂回できる。

手段の優先順位: **公式に「人が押す前提」の入口があればそれを使い、DOM 操作は公式の入口が無い媒体に限る。**

| 媒体 | 手段 | 難易度 | 画像/動画 | 備考 |
|---|---|---|---|---|
| **X** | **Web Intent**(`x.com/intent/post?text=...`)で投稿画面を本文入りで開く | ◎ | ✗(intent では添付不可) | X 公式の仕組み。DOM に触らず、費用ゼロ、壊れない。まずこれ |
| X(画像付き) | content script で投稿欄に本文、file input に画像をセット | ○ | ✓ | DOM 依存。X は自動化に厳しいので一投稿ずつを厳守 |
| **TikTok** | `tiktok.com/upload` に動画・キャプションをセット | ○ | ✓ | DOM 依存。代替は公式 API の Upload(受信箱)モード = 本人がアプリで投稿 |
| **Instagram** | Web 版「作成」ダイアログに画像とキャプションをセット | △ | ✓ | DOM が難読化・変更頻繁、下書き機能なし。モバイル前提の媒体。最後 |

X と Meta は note と違い「自動化されたアクセス」を規約で明示的に禁止している。本人のタブの投稿欄を埋める行為は既存の拡張(SocialDog、Typefully)と同じ範囲だが灰色であることは変わらないため、「人が押す」に加えて一投稿ずつを固定する。

着手順は需要次第だが、既定は X(Web Intent)→ TikTok → Instagram。X の Web Intent 版は実装が小さく、note の実機検証と並行できる。

構成は `selectors/note.json` と同じ発想で媒体ごとに分ける。front matter に `platforms` を持たせ、1 本の入力から複数媒体の下書きを開く。

```yaml
---
platforms: [note, x]
title: 記事タイトル          # note
hashtags: [AI, 個人開発]     # 共通
thumbnail: ./thumb.png
x_text: |                    # X 用の短文は AI 側に書かせる(ツールは要約しない)
  記事を書きました → {url}
---
```

```
selectors/
  note.json / x.json / tiktok.json / instagram.json
```

## やらないこと

- 投稿・公開ボタンの自動クリック(全媒体)
- 利用者の認証情報(Cookie・パスワード・トークン)をサーバーで預かる構成
- サーバーを介した Web サービス化のうち、SNS への投入を含むもの(投入はローカルの拡張 / CLI に限る)
- 非公式 API による完全自動投稿
- 一度に複数投稿を連続で投入する機能
- AI による生成・要約(入力は AI 側で完成させる)

## 参考(2026-10 時点)

- note 公式 API: 2026-10-08 提供開始。note pro 契約企業向け、ソリューションパートナー経由。下書き保存まで、公開は画面から、見出し画像・有料設定は非対応
- note 迷惑行為への対応強化: 2026-02-27。対象は機械的な大量登録・投稿、スパム、外部サービスを利用した組織的な悪用
- X API: 無料枠は新規に提供なし。Basic は新規受付終了。2026-02 から前払い従量課金(投稿 $0.015、リンク付き $0.20)
- TikTok Content Posting API: 未 audit のクライアントは非公開投稿のみ。Upload モードは本人が投稿するため audit 前でも実用可
- Instagram Graph API: プロアカウント必須。Instagram Login 方式なら Facebook ページ連携不要。24 時間 100 件まで
